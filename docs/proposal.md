# 城巡りアプリ 企画案

城巡りアプリ（Castle Go）の目的・機能・データ取得方針・開発工程をまとめる．
対象読者は，アプリを実装する開発者と AI エージェント．
城のデータは castle-wiki（Cloudflare D1 を使う自作の API）から取得する．
アプリが使うデータの構造は，本書の「データの階層」に記す．API の仕様は [想定する API](api.md) に分ける．

## 概要

### 目的

城の位置情報を地図と一覧で確認し，訪問を記録できるアプリを作る．
車・電車・自転車・徒歩など，さまざまな移動手段で城を巡る場面を想定する．
スマートフォンのアプリを基本とし，車では Android Auto の車載ディスプレイでも，現在地と周辺の城を確認できる．

### 基本方針

| 項目 | 内容 |
| ---- | ---- |
| 移動手段 | 車・電車（公共交通）・自転車・徒歩を想定．移動手段を問わず，一覧・地図・詳細はスマートフォンで使える．Android Auto は車での追加の手段 |
| 開発環境 | Android Studio，Kotlin のみ |
| スマートフォンの UI | Jetpack Compose |
| Android Auto | Android for Cars App Library．POI（Point of Interest）アプリとして実装 |
| ナビゲーション | Google マップなどの外部アプリに委譲．ルート計算と音声案内は対象外 |
| データの出所 | castle-wiki の API．アプリでは城の追加・編集・削除を行わない |
| データの保持 | 端末内の Room．画面と車載はすべて Room のみ参照（オフラインファースト） |
| API リクエスト | 減らす．同期は差分のみ，詳細は必要時のみ，写真はキャッシュ |

### 技術スタック

| 分類 | 技術 |
| ---- | ---- |
| 言語 | Kotlin |
| UI | Jetpack Compose |
| Android Auto | Android for Cars App Library（例：1.7.0．実装時に最新の安定版を確認すること） |
| アーキテクチャ | MVVM |
| 非同期処理 | Kotlin Coroutines |
| データ管理 | Room |
| 通信 | Retrofit または Ktor，kotlinx-serialization |
| 画像 | Coil |
| 定期同期 | WorkManager |
| 位置情報 | Fused Location Provider |
| スマートフォンの地図 | Google Maps Compose．API キーは `local.properties` で管理し，コミットしない |
| ビルド | Gradle Kotlin DSL |

- `minSdk` は 26 とする（現在の設定は 34 のため，変更すること）

## データ取得の方針

### 全体像

```text
castle-wiki API ──(差分同期)──> Room（ミラー） ──> スマートフォンの UI
                                      └────────> Android Auto
```

- 画面と車載は，API を直接呼ばず，Room のみを読む
- 通信が不安定な場所（トンネル・山間部）でも，一覧・地図・車載が動く
- 地図の表示範囲ごとに API を呼ぶ方式は採らない
  - 一覧用の属性のみなら全件を端末に持てるため

### データの階層

| 階層 | 内容 | 取得元 | 取得タイミング |
| ---- | ---- | ------ | -------------- |
| 一覧ミラー | `castles` の写し列（下記） | 差分同期 API | 初回は全件，以降は差分 |
| タグ辞書 | `castle_tags`，`castle_tag_assignments` | 差分同期 API に同梱 | 一覧ミラーと同時 |
| 城の詳細 | 最新版の本文（`body`）と属性（`attributes`） | 詳細 API | 詳細画面を開いたときのみ |
| 写真 | 代表写真の 400px の WebP | 写真の API | 表示時．端末にキャッシュ |
| 利用者の状態 | 訪問済み，訪問日時，メモ | 端末のみ | API は使わない |

一覧ミラーの列は，wiki の `castles` テーブル（最新版の属性の写し）のうち次の列とする．

| 列 | 用途 |
| -- | ---- |
| `id`，`current_revision_number` | 識別，詳細キャッシュの版の比較 |
| `name`，`name_kana`，`search_text` | 表示，読み仮名順，検索 |
| `lat`，`lng` | 地図，距離，ナビゲーション |
| `scale`，`castle_kind`，`location_type` | 絞り込み，ズーム別の間引き |
| `prefecture`，`tenshu_status` | 絞り込み，車載の基本情報 |
| `meijo_selection`，`meijo_number` | 名城の選定の判定，番号の表示，絞り込み |
| `primary_photo_id` | 代表写真 |
| `updated_at`，`deleted_at` | 差分同期，削除の反映 |

列の型と値の意味は次のとおり．

| 列 | 型 | 意味 |
| -- | -- | ---- |
| `id` | 文字列 | 城の ID（UUID v7） |
| `current_revision_number` | 整数 | 最新版の版番号 |
| `lat`，`lng` | 小数 | 緯度（-90〜90），経度（-180〜180） |
| `scale` | 整数 | 規模（1〜6） |
| `castle_kind` | 文字列，NULL 可 | 城の種別．`castle`（城），`jinya`（陣屋），`fort`（砦），`yakata`（館），`gusuku`（グスク），`chashi`（チャシ），`other`（その他） |
| `location_type` | 文字列，NULL 可 | 立地．`yamajiro`（山城），`hirayamajiro`（平山城），`hirajiro`（平城），`mizujiro`（水城） |
| `prefecture` | 文字列，NULL 可 | 都道府県．JIS X 0401 のコード（`01`〜`47`） |
| `tenshu_status` | 文字列，NULL 可 | 天守の状態．`existing`（現存），`wooden_restoration`（木造復元），`exterior_restoration`（外観復元），`revival`（復興），`mock`（模擬） |
| `meijo_selection` | 文字列，NULL 可 | 名城の選定．`top100`（日本100名城），`continued_top100`（続日本100名城） |
| `meijo_number` | 整数，NULL 可 | 名城の選定の番号．`meijo_selection` と同時に NULL または値あり |
| `primary_photo_id` | 文字列，NULL 可 | 代表写真の ID |
| `updated_at`，`deleted_at` | 整数（ミリ秒の Unix 時刻），`deleted_at` は NULL 可 | 最新版の作成日時，論理削除した日時 |

- 値が不明・未入力の列は NULL とする．端末は NULL を許容して表示する
- 列挙の値は将来増える可能性があるため，端末は未知の値を「その他」として扱う
- Room にも `scale`，`lat`，`lng`，`prefecture` の索引を張り，絞り込みをローカルで行う
- 代表写真の URL は `/api/photos/<primary_photo_id>/images/400` で決まるため，追加の API は不要

### 同期のしくみ

```text
初回   → 全件取得（ページング）→ Room に保存 → カーソルを保存
2回目〜 → カーソル以降の差分を取得 → 追加・更新・削除を反映 → カーソルを更新
差分なし → 304 Not Modified（ETag）
```

| 項目 | 内容 |
| ---- | ---- |
| カーソル | `updated_at` と `id` の組．削除・復元も版になり `updated_at` が変わるため，差分で検知できる |
| 削除 | `deleted_at` が入った行として届く．端末側でも削除済みとして扱う |
| 起動条件 | WorkManager の定期実行（例：1日1回，Wi-Fi・充電時），アプリ起動時に最終同期から一定時間（例：6時間）超過，手動更新 |
| 車載での同期 | Android Auto の接続中は同期しない |
| 初回の通信 | APK に同梱したスナップショットを初期値にし，初回も差分のみにする（下記） |

### 同梱スナップショット

- ログインは不要．同梱スナップショットも，最新の取得も，ログインなしで使える（[想定する API](api.md#認証)）

ビルド時に全件を取得して APK に入れ，初回起動の全件取得を省く．

```text
ビルド → Gradle のタスクが /sync/castles を全ページ取得
       → snapshot.json.gz（城・タグ・nextCursor・serverTime）を assets/ に出力
初回起動 → assets を読み，Room に一括 insert → sync_state にカーソルを保存
2回目〜  → 通常の差分同期（スナップショット以降の更新分のみ）
```

| 項目 | 内容 |
| ---- | ---- |
| 方式 | JSON を同梱し，初回起動で Room に取り込む．事前作成の Room DB（`createFromAsset`）は，スキーマの `identityHash` との一致が必要で生成が複雑なため採らない |
| 取得の対象 | リリースビルドと CI のみ．デバッグビルドは空のスナップショットか，前回の取得結果を使い，ビルドをネットワークに依存させない |
| 含める行 | `deletedAt` が NULL の城のみ |
| 更新 | 同期の列を追加したときは，スナップショットのバージョンを上げて再取得する |
| サイズ | gzip で 1 MB 未満の見込み（例） |

### 詳細画面のキャッシュ

```text
詳細画面を開く
→ Room の current_revision_number と，詳細キャッシュの版を比較
→ 一致 → API を呼ばない
→ 不一致または未取得 → 詳細 API を1回呼び，版つきで保存
```

### リクエスト数の目安

| 操作 | リクエスト数（例） |
| ---- | ------------------ |
| 通常の1日 | 同期 0〜1回（差分なしなら 304） |
| 詳細画面 | 初めて開く城，または版が変わった城のみ 1回 |
| 写真 | 初回表示のみ．以降はキャッシュ |
| Android Auto | 0回 |

### 件数と性能の目安

城の数は約 1 万件を想定する．

| 項目 | 見積もり（例） | 対応 |
| ---- | -------------- | ---- |
| 一覧ミラーのサイズ | 1 行 約 300 B → 約 3 MB（gzip で 約 0.5〜0.8 MB） | 全件を端末に持つ |
| 初回の全件取得 | `limit` 1000 で 10 リクエスト | 初回のみ．APK に同梱したスナップショットを初期値にすれば，初回も差分のみにできる |
| 検索（`search_text` の `LIKE`） | 1 万行の走査で数ミリ秒〜数十ミリ秒 | そのまま使う．遅い場合は全文検索（FTS）を検討 |
| 距離順・周辺の城 | 緯度経度の範囲で絞ってから距離を計算 | 索引を使い，全件の距離計算は避ける |
| 一覧の表示 | 1 万行を一度に読まない | Paging 3 で必要な分だけ読む |
| 地図のマーカー | 1 万個を一度に描くと重い | 表示範囲の城のみ描き，規模で間引き，密な場所はクラスタにする |
| Android Auto | 近い N 件のみ | 緯度経度の範囲で絞った後に上位 N 件を返す |
| 同期の差分 | 通常は数件〜数十件 | カーソルで `updated_at` 以降のみ取得 |

- 初回のカーソル移動で大量の行が同じ `updated_at` を持つ場合（一括登録）も，カーソルが `updated_at` と `id` の組のため取りこぼさない
- サーバー側には，差分取得用に `castles` の `updated_at`，`id` の索引が必要（wiki の `castles` には地図・都道府県・読み仮名の索引のみで，`updated_at` の索引がない）．索引がないと，同期のたびに全行を走査する

## 移動手段ごとの設計

### 想定する場面

| 移動手段 | 典型的な場面 | 画面を見る状況 | 主に使う機能 |
| -------- | ------------ | -------------- | ------------ |
| 車 | 城から城へ移動．目的地の選択 | 運転中は Android Auto．停車中はスマートフォン | 周辺の城，ナビ起動 |
| 電車（公共交通） | 車窓から見える城の確認．最寄り駅からの訪問計画 | 座って操作．トンネルで圏外になる | 地図，一覧，オフライン表示 |
| 自転車 | 数 km〜数十 km の周遊．休憩中に次の城を探す | 走行中は見ない．休憩中に操作 | 周辺の城，ナビ起動（自転車） |
| 徒歩 | 城内・城下町の散策．城同士が近い街歩き | 歩きながら片手で操作 | 現在地と城の地図，詳細，訪問記録 |

### 設計への反映

| 項目 | 方針 |
| ---- | ---- |
| 移動手段の設定 | 設定画面で既定の移動手段（車・公共交通・自転車・徒歩）を選べる．詳細画面のナビ起動時にも切り替えられる |
| 移動手段の推定 | Activity Recognition API の結果を「提案」として使い，利用者が上書きできる（下記） |
| 周辺の範囲 | 移動手段に応じた既定の半径を使う（例：徒歩 2 km，自転車 10 km，車・公共交通 50 km）．利用者が変更できる |
| 距離の表示 | 現在地との直線距離を表示する．所要時間は外部の地図アプリに任せる |
| ナビ連携 | 移動手段を外部アプリに引き継ぐ（例：Google マップの URL の `travelmode`．`driving`・`transit`・`bicycling`・`walking`） |
| オフライン | 電車のトンネルや山間部でも，一覧・地図・訪問記録が動く．地図のタイルは Google マップの標準の保持に任せる |
| 位置情報 | 前面表示中のみ取得する．移動手段が車・電車の場合は更新間隔を長くし，徒歩では短くする（電池の節約） |
| 操作 | 走行中の操作を促さない．大きいタッチ領域と，片手で操作できる画面にする |
| Android Auto | 車のみ．ほかの移動手段では使わない |

### 移動手段の推定

加速度センサーを自前で解析せず，Google Play 開発者サービスの Activity Recognition API を使う．

| API の値 | 推定する移動手段 | 備考 |
| -------- | ---------------- | ---- |
| `WALKING`，`RUNNING`，`ON_FOOT` | 徒歩 | |
| `ON_BICYCLE` | 自転車 | 誤検知がある |
| `IN_VEHICLE` | 車または公共交通 | 区別できない |
| `STILL` | 変更しない | 直前の移動手段を維持する |

| 項目 | 方針 |
| ---- | ---- |
| 車と公共交通の区別 | Android Auto に接続している間は車．未接続の `IN_VEHICLE` は区別せず，周辺の半径は共通の既定値を使う．ナビ起動時に利用者が選ぶ |
| 扱い | 提案にとどめ，確定しない．利用者の手動の選択を常に優先する |
| 実行 | 前面表示中のみ．常時の登録や背景での取得は行わない |
| 権限 | `ACTIVITY_RECOGNITION`（実行時の権限）．拒否された場合は手動の設定のみで動く |
| 反映先 | 周辺の半径の既定値，位置情報の更新間隔，ナビ起動時の既定の移動手段 |
| プライバシー | 推定は端末内で完結し，サーバーに送らない |

- 推定には遅延（数十秒）と誤検知がある．重要な処理を推定結果だけに依存させない

- 「車窓の城の通知」は，MVP の対象外とする（将来の検討事項）
  - 内容：電車で移動中に，アプリを開いていなくても，近くの城に近づいたら通知する機能
  - 対象外の理由：画面を閉じている間も位置情報を取得するため，背景での位置情報の権限（常に許可），通知の権限，電池の消費への対応が必要になる
  - 実現する場合は，ジオフェンス（城の周囲に設定した円への出入りの検知）を使う
  - 通知する城は，規模（`scale`，1〜6）で絞れる．設定した値以上の城のみを通知する（例：4 以上）
    - 小さな城まで通知すると頻繁になるため，既定は大きい規模のみとする（例）
    - 絞り込みは端末の `castle` から行い，API は使わない
    - 規模のほか，100名城・続100名城，未訪問のみ，での絞り込みも将来の候補とする
  - 城が車窓から見えるかどうかは，緯度経度だけでは判断できない．路線のデータがないため，通知は「近づいた」という内容にとどまる
- 最寄り駅・路線のデータは wiki にないため，MVP では扱わない．公共交通は外部アプリのルート検索に任せる

## 機能要件

### スマートフォン

| 機能 | 内容 | API |
| ---- | ---- | --- |
| 城一覧 | 現在地からの距離順．城名・距離を表示し，詳細へ遷移 | 不要 |
| 検索 | 城名・読み仮名・別名（`search_text`） | 不要 |
| 絞り込み | 都道府県・規模・城の種別・天守の状態・立地・名城の選定・タグ | 不要 |
| 地図 | 現在地と城のマーカー．表示範囲の城のみを描き，規模に応じてズーム別に間引き，密な場所はクラスタにする．マーカー選択で概要を表示 | 不要 |
| 周辺の城 | 「周辺の表示」の設定（上位 N 件，または半径 N km 以内）に従う．半径の既定値は移動手段ごとに変わり，変更できる | 不要 |
| 城詳細 | 本文・属性・代表写真・現在地からの距離．外部ナビへの目的地設定（移動手段を選択） | 初回のみ |
| 訪問記録 | 訪問済み・訪問日時・メモ．100名城・続100名城それぞれの進捗 | 不要 |
| 設定 | 既定の移動手段・周辺の表示（方式と N）・車載の近づいた通知（オン・オフ，距離，規模の下限など）・同期の状態・手動更新・キャッシュの削除 | 差分同期のみ |

### Android Auto

POI アプリとして動作し，`PlaceListMapTemplate` を使う．地図はホスト側が描画する．

| 機能 | 内容 | API |
| ---- | ---- | --- |
| 地図の基本表示 | 接続中は，現在地と周辺の城の地図を常に表示する．最初の画面を地図付きの一覧（`PlaceListMapTemplate`）にする | 不要 |
| 周辺の城 | 設定の「周辺の表示」に従い，近い順の上位 N 件，または半径 N km 以内の城を地図と一覧に表示（下記） | 不要 |
| 近づいた通知 | 設定した距離（例：1 km）以内に城が近づいたら，車載に通知を出す（下記） | 不要 |
| 絞り込み | 100名城・続100名城の未訪問のみ，など | 不要 |
| 基本情報 | 名称・読み仮名・都道府県・天守の状態・名城の番号 | 不要 |
| ナビゲーション連携 | 選択した城の緯度・経度を外部ナビアプリに引き継ぐ | 不要 |
| 一覧の更新 | `OnContentRefreshListener` で現在地を取り直して再描画 | 不要 |

#### 周辺の表示（スマートフォンと共通）

利用者が次の2つから選び，値 N を設定する．スマートフォンの「周辺の城」と Android Auto で共通の設定とする．

| 方式 | 内容 | N の例 |
| ---- | ---- | ------ |
| 件数（Top-N） | 現在地から近い順の上位 N 件 | 20 件 |
| 半径（N km） | 現在地から N km 以内の城（近い順） | 移動手段の既定値（徒歩 2 km，自転車 10 km，車・公共交通 50 km）から変更 |

- Android Auto は，テンプレートの件数の上限（実装前に確認すること）を超える場合，上限までに切り詰める
- 半径の場合に件数が多いときは，近い順に上限まで表示し，残りは省略する
- 絞り込み（規模・100名城・続100名城・未訪問）との併用ができる
- 計算は端末の `castle` から行い，API は使わない

#### 近づいた通知

接続中に，城に近づいたら車載に通知する．スマートフォンの背景での通知（[車窓の城の通知](#移動手段ごとの設計)）とは別の機能とする．

| 項目 | 内容 |
| ---- | ---- |
| 動作する条件 | Android Auto の接続中のみ．接続していない間は動かない |
| 通知する距離 | 設定で変更（例：1 km） |
| 対象の城 | 規模（`scale`）の下限（例：4 以上），100名城・続100名城，未訪問のみ，で絞れる．既定は大きい規模のみ（例） |
| 重複の防止 | 通知した城の ID と日時を端末に保存し，同じ城を一定時間（例：24 時間）は再通知しない |
| 内容 | 城名・距離・天守の状態．押すと城の基本情報の画面へ |
| 位置の判定 | 接続中の現在地の更新ごとに，端末の `castle` から距離を計算する．ジオフェンスは使わない |
| 権限 | 通知の権限．位置情報の権限は，スマートフォン側で許可しておく |

- 通知の表示方法（`CarAppExtender`，ヘッドアップ表示の可否）は，POI アプリのカテゴリでの制約を実装前に公式ドキュメントで確認すること
- 運転の妨げにならないよう，通知の頻度に上限を設ける（例：10 分に 1 回）

- 車載には本文や長文を出さない．詳細はスマートフォンで見る
- 運転中の操作制限とテンプレートの制約（件数・画面の深さ）に従う

### 対象外

| 項目 | 理由 |
| ---- | ---- |
| 城の追加・編集・削除 | castle-wiki 側の責務 |
| ルート計算・音声案内 | 外部ナビアプリに委譲 |
| 訪問記録のアカウント同期 | 当面は端末のみ．将来の検討事項 |

## 想定する API

wiki 側に，読み取り専用の `GET` の API を要望する．仕様は [想定する API](api.md) にまとめる．

| エンドポイント（例） | 役割 | 呼ぶタイミング |
| -------------------- | ---- | -------------- |
| `GET /sync/castles` | 一覧用の列の差分（削除を含む） | 初回・定期同期・手動更新 |
| `GET /sync/castle-tags` | タグ辞書と，城とタグの対応 | 同上 |
| `GET /castles/{id}` | 最新版の本文・属性・写真の一覧 | 詳細画面を開いたとき |
| `GET /api/photos/{id}/images/{size}` | 写真の WebP（既存の API） | 表示するとき |

## データ設計（端末）

| テーブル | 内容 |
| -------- | ---- |
| `castle` | 一覧ミラー．wiki の `castles` の写し列 |
| `castle_tag` | タグ辞書 |
| `castle_tag_assignment` | 城とタグの対応 |
| `castle_detail` | 詳細のキャッシュ．`castle_id`，`revision_number`，`body`，`attributes`（JSON） |
| `visit` | 訪問記録．`castle_id`，`visited_at`，`memo` |
| `sync_state` | 同期のカーソル・最終同期日時 |
| `notified_castle` | 車載で通知した城．`castle_id`，`notified_at`．重複通知の防止に使う |

- `castle` を直接編集しない．同期のみが書き込む
- 訪問記録は `castle` と別テーブルにし，同期で上書きされないようにする

### 端末で計算する値

次の値は API にも `castle` にも持たず，端末で `castle` と `visit` から計算する．

| 値 | 計算 |
| -- | ---- |
| 100名城の進捗 | 分母は `meijo_selection = 'top100'` の城の数．分子はそのうち `visit` に記録がある城の数 |
| 続100名城の進捗 | 分母は `meijo_selection = 'continued_top100'` の城の数．分子の数え方は100名城と同じ．100名城と別々に集計する |
| 未訪問の100名城・続100名城 | `meijo_selection` が該当し，`visit` に記録がない城．Android Auto の絞り込みにも使う |
| 現在地からの距離・周辺の城 | `lat`，`lng` と現在地から計算 |

## アーキテクチャ

MVVM を採用する．

```text
UI（Compose / Car App の Screen）
→ ViewModel（Car App では Screen）
→ Repository（CastleRepository，SyncRepository，VisitRepository）
→ Room / API / Location
```

- スマートフォンと Android Auto は，同じ Repository を通じて同じ Room を参照する

## Android Auto の実装方針

| 項目 | 内容 |
| ---- | ---- |
| サービス | `CarAppService` の intent-filter に `androidx.car.app.category.POI` を宣言 |
| 権限 | `androidx.car.app.MAP_TEMPLATES` を Manifest に宣言 |
| 依存 | `androidx.car.app:app`，`androidx.car.app:app-projected` |
| 画面 | 城一覧・地図（`PlaceListMapTemplate`）→ 城詳細 → 外部ナビ |
| 現在地 | スマートフォン側で位置情報の権限を先に許可しておく |
| 件数 | 現在地から近い順に上位 N 件に絞る |

- スマートフォン側の地図 UI は車載に流用しない
- 外部ナビの起動（`geo:` などの Intent を `CarContext.startCarApp()` で渡す方式）が POI アプリで使えるかは，実装前に公式ドキュメントで確認すること
- 利用できる API とテンプレートは，ホストの Car API レベルに依存するため，実装前に確認すること

## MVP

1. wiki から城の一覧を同期し，端末に保持する
2. スマートフォンで城の一覧を表示する
3. 現在地を取得する
4. Android Auto で地図と周辺の城を表示する
5. 城を選択する
6. Google マップに目的地と移動手段を引き継ぐ
7. スマートフォンで，現在地の周辺（半径を指定）の城を一覧・地図で見る

訪問記録・詳細画面の本文と写真・絞り込み・車窓の城の通知は，MVP の後に追加してよい．

## 完成条件

次をすべて満たした時点で MVP 完成とする．

- Android スマートフォンにインストールできる
- 城の一覧を表示できる
- 現在地を取得できる
- 機内モードでも，同期済みの城の一覧と Android Auto の表示が動く
- Android Auto に接続でき，地図上に現在地と複数の城を確認できる
- 城を選択し，移動手段（車・公共交通・自転車・徒歩）を指定して外部ナビゲーションアプリに引き継げる
- 差分なしの同期で，城の本文を再取得しない
